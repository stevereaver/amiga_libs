# MASH 1.98 vs siblings (1.16, 2.0)

- Same wire format family as xpkMASH 1.16/2.0 (committed siblings):
  flag-slot + raw-byte hybrid emitter, unary-class gamma distances.
- 1.98 carries TWO engines behind one format ("2 mixed streams"):
  - inputs < 0x10001 use the V2.0-style gap-array matcher
    (`AllocMem(0x20010 + 2*inlen)`), and
  - larger inputs (or alloc failure) fall back to the V1.16-style
    hash-chain engine (`AllocMem(0x10000)` chain table plus a
    halving work alloc 0x20000 → 0x2000 over 5 attempts).
- Compression levels differ: 1.98 `xm_PackSpeed`=17,
  `xm_UnpackSpeed`=400, `xm_Ratio`=472 (0x1d8).
- The 000 and 020 builds are functionally identical; the 020 build
  uses 68020 code forms in the hot matcher loops (body 52 bytes
  shorter, same data layout and vector offsets).
- Codec transliteration for the format: `work/xpkMASH_ref.c`.
