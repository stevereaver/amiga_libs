# xpkLIN2.library V1.1(000) — reverse engineering index

XPK compression sublibrary, "Lino2 V1.1" by Gerhard Tuenkler
(1 Oct 2013). Per its own descriptor: **"Better version of Lino1"** —
a Lempel-Ziv packer ("LIN" family, fourcc `LIN2`). Same library
skeleton generation as xpkDUKE/xpkNUKE 1.8 (word-offset functab,
`rt_EndSkip=0`, `dataSize 0x26`).

## Files

- `binary/xpkLIN2_1.1(000).library` — original, 3152-byte file,
  single CODE hunk (0x2f2 longwords = 3016 bytes at file offset 0x20).
  MD5 `8b941020dcb8451eefe40c09be5f6993`.
- `source/` — byte-identical reconstruction (verbatim mnemonic
  transcription):
  - `xpkLIN2.s` — whole hunk: RomTag/InitTable/datatab/functab/
    vectors/codec/XpkInfo, generated by `work/genasm.py`
  - `Makefile` — `m68k-amigaos-gcc -m68000 -nostdlib -nostartfiles
    -Wl,-s`
  - built artifact: `source/xpkLIN2.library` (BYTE-IDENTICAL,
    same MD5)
- `work/` — `genasm.py` (transliterator), `fixup.py` (auto-.short
  patch loop, converged after 13 patches), `patch000.txt`,
  `code.bin`/`dis.txt` (extracted hunk + full disassembly),
  `oracle.py` (machine68k harness), `run_O.log`/`run_R.log`
  (identical), `streamsO/` + `streamsR/` (20 packed fixtures,
  byte-identical).

## Result

**BYTE-IDENTICAL** rebuild (MD5 match) and **RUNTIME-IDENTICAL**
oracle: same pack bitstreams, same return codes (-7/-14/-17/-32
paths all exercised), same lifecycle trace, same log of exec calls.
