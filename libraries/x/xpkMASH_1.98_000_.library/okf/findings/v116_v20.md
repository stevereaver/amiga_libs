# Position in the family

MASH 1.98 ("good packer") sits between 1.16 ("another LZ77-family",
the broken one) and 2.0 ("Mashiner V2.0").  Same MSB-first mixed
bit/literal wire format and same 32KB window throughout.

| | 1.16 | **1.98 (000)** | 1.98 (020) | 2.0 |
|---|---|---|---|---|
| file bytes | 2036 | 2816 | 2796 | 2100 |
| code hunk | ~1900 | 2652 | 2632 | 1980 |
| relocs | ? | 28 | 28 | 17 |
| functab | long offsets | **absolute longs** | absolute longs | word offsets |
| engines | hash-chain | **gap-array + hash-chain** | same | gap-array |
| idstr | V1.16 | V1.98 _000 | V1.98 _020 | V2.0 |
| rt_Version | 1 | 1 | 1 | 2 |
| bound | inlen-50 | **inlen-10** | inlen-10 | ? |
| len-2 dist>=512 | dropped (dead add carry) | dropped | dropped | ? |
| LibInit gate | none | none | none | AFB_68020 btst (020 build) |

# What 1.98 changed vs 1.16

- **New primary engine**: for inlen < 0x10001 a single
  `0x20010 + 2*inlen` allocation runs the gap-array (V2.0-style)
  matcher: pass1 builds `gaps[i]` = distance-to-previous-pair, pass2
  is a lazy gap-chain matcher writing 6-byte `{pos.w,dist<<16|len-2}`
  records.  1.16 only had the hash-chain engine.
- **The 1.16 hash-chain engine survives as engine B** for big inputs
  or when the big alloc fails: AllocMem(0x10000) chain table +
  work alloc halving 0x20000->0x2000 (5 tries).
- **Pack bound tightened**: output must beat input by >= 11 bytes
  (`OutBuf+InLen-10`), vs 1.16's 50.  Inputs < 11 bytes return -17.
- **len-2 dist >= 512 still dropped** — the 1.16 defect is carried
  over (emit rejected on both engines).
- **Descriptor**: gains the `_000`/`_020` CPU suffix in the
  version string and `masterver` word = 2; "good packer" long name.
- **functab**: 1.98 uses absolute-long entries (relocated); 1.16
  used the same; 2.0 moved to the word-offset (0xffff marker)
  flavour.

# What 1.98 keeps broken from 1.16

- lazy lookahead reads past InBuf end (uncapped hashing at cur>=end)
- chain table sign-extension aliasing (engine B only)
- unbounded class-walk decode tables; decoder trusts the stream
  completely (distance-0 reads, 2-byte overwrite past OutBuf end,
  trailing-garbage tolerance)
- 16-bit `emit_gamma` span register -> hangs on runs/lengths
  >= ~32K

# 000 vs 020 within 1.98

- Functionally identical: every packed stream in the corpus is
  byte-identical between builds; only the `_020` id/long-name
  strings differ.
- Codegen differences only: 68020 scaled-index addressing fuses the
  000's `lea (a3,d1.l),a5; adda d1,a5` pairs into
  `lea (a3,d1.l*2),a5`, `tst.w -4(a2,d3.w*2)` etc.  Body 20 bytes
  shorter (2632 vs 2652).
- Code is byte-identical through 0x356 (all entries, XPK info,
  init); the 2-byte fill there differs (000: `001c`, 020: `4b90` =
  `chk.w (a0),d5`) — dead in both; the clear loop is entered via
  `bsr.w $358` in each build.

# What 2.0 later dropped

- The hash-chain fallback engine (2.0 is gap-array only) and its
  chain-table defects.
- Functab moved to word-offsets; LibInit on 020 gained the
  AFB_68020 AttnFlags gate.

# Observed 1.98 streams

- `Z`*300 -> 6 bytes `bf 5a c5 20 20 00` (both builds)
- `Z`*40000 -> 12 bytes; 66000-byte ramp -> 764 bytes
- Incompressible/short input -> rc -17; alloc failure -> rc -7
